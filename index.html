02 / Método de trabajo

Primero el problema.
Luego el HTML.

Un buen prompt define a quién ayuda la herramienta, qué debe permitir hacer y cómo se comprobará que funciona. El código es una respuesta a esa definición.

01 / DEFINIR

Situación concreta

¿Qué decisión, explicación o registro necesita la persona?

02 / SUSTENTAR

Contexto y fuentes

Aporta tus datos, límites, material revisado y lenguaje del público.

03 / CONSTRUIR

Interacción útil

Pide una acción real: explorar, comparar, registrar o preparar.

04 / COMPROBAR

Prueba y ajuste

Abre el archivo, pulsa cada control y revisa contenido y privacidad.

03 / Biblioteca editable

Nueve puntos de partida.

Reemplaza el texto entre corchetes con tu propio caso. Los prompts 07–09 forman una secuencia: crear una guía editorial, mejorarla y extraer una herramienta móvil. Se reconstruyeron a partir de nuestro proceso de diseño; no son una transcripción literal de un único prompt.

01 / 09Educación

Una lección, una pantalla

Convierte una clase o transcripción en un bloque breve que refuerce las ideas principales sin repetir toda la sesión.

Necesitas: lección, guion o resumen revisado.
Ver prompt completo
Toma esta lección del curso «Introducción a la IA en nutrición» y conviértela en un bloque HTML de refuerzo para nutriólogos y entrenadores no técnicos.

Irá debajo de un video o audio. Su función es fijar criterio en menos de dos minutos de lectura.

Incluye:
1. Una idea central.
2. De cuatro a seis principios, cada uno con título, explicación breve y aplicación profesional.
3. Una traducción práctica a consulta, entrenamiento o educación.
4. Una frase final memorable.

Usa HTML semántico y fácil de insertar en una plataforma. Evita párrafos largos, tecnicismos, CSS y formato de artículo. Usa únicamente section, div, h2, h3, p, ul, li, strong y span.

02 / 09Educación

Infografía viva · 3-6-9

De una pregunta fisiológica a una experiencia donde el alumno predice, manipula, observa y explica.

Necesitas: pregunta de aprendizaje y contenido revisado.
Ver prompt completo
Diseña un HTML interactivo para la sesión educativa «[TEMA]» del sistema 3-6-9.

Pregunta que el alumno debe resolver: [PREGUNTA].
Fuente o contenido revisado: [PEGAR].
Público: [NIÑOS / ATLETAS / ENTRENADORES / PACIENTES].

La experiencia debe avanzar así: observar un fenómeno → formular una predicción → cambiar una variable → ver qué ocurre → explicar el mecanismo → tomar una decisión.

Incluye una explicación inicial muy breve, una visualización que cambie de verdad al interactuar, dos preguntas de comprobación y una acción final. Señala qué partes provienen de la fuente y cuáles son simplificaciones didácticas.

Entrega un único HTML con CSS y JavaScript internos, adaptable a celular. Cada control debe funcionar. No inventes resultados científicos ni referencias. Al final, explica cómo comprobaste las interacciones.
Salida: infografía interactiva.

04 / 09Consulta

Guía de competencia en 3 capítulos

Ordena viaje, alimentación y carrera en una misma ruta para que el atleta sepa qué hacer en cada transición.

Necesitas: itinerario, plan y alimentos ya probados.
Ver prompt completo
Convierte esta estrategia de nutrición deportiva en una guía HTML para atletas que viajarán y competirán.

Organiza la experiencia en tres capítulos navegables:
1. Logística: viaje, alojamiento, compras, bolsa de competencia y decisiones que deben quedar resueltas.
2. Alimentación: comidas conocidas, horarios, hidratación y ajustes según tolerancia.
3. Día de carrera: secuencia desde el despertar hasta la recuperación.

Muestra una línea de tiempo y listas que se puedan marcar. Si hay dos atletas, conserva una estructura común, pero separa claramente sus diferencias. Usa únicamente alimentos, productos, cantidades y horarios que aparezcan en los datos; deja visible lo que falta confirmar.

Prioriza lectura en celular. El HTML debe ser autónomo, con navegación y casillas funcionales. Revisa que no haya contradicciones entre capítulos antes de entregar el código completo.

Datos y estrategia:
[PEGAR INFORMACIÓN ANONIMIZADA]
Salida: guía móvil de competencia.
05 / 09Campo

Fuel Kit × HYROX

Diseña un registro para probar combustible en entrenamiento y observar la relación entre momento de consumo y tolerancia.

Necesitas: decidir qué registrar y cómo comparar sesiones.
Ver prompt completo
Crea un único archivo HTML llamado «Fuel Kit × HYROX» para que un atleta o nutriólogo registre lo que prueba durante una sesión de entrenamiento.

Debe permitir anotar: producto o alimento, cantidad, momento de consumo, duración e intensidad de la sesión, facilidad de uso, síntomas gastrointestinales y comentario libre. Después debe mostrar una línea de tiempo y un resumen de lo que se toleró mejor.

Distingue «dato registrado» de «interpretación». No diagnostiques intolerancias ni recomiendes automáticamente geles, líquidos o sodio. Incluye una vista para comparar dos sesiones y exportar los registros a CSV.

Diseño claro, táctil y usable en celular. Funciona sin servidor ni cuentas. Usa datos ficticios para la demostración y ofrece un botón para borrarlos. Prueba guardar, editar, comparar, exportar y reiniciar; no dejes botones decorativos.
Salida: herramienta de registro.
06 / 09Simulación

Mejorar un simulador existente

Convierte una visualización del exposoma en una experiencia donde el alumno compara escenarios y distingue datos de inferencias.

Necesitas: un HTML inicial y una pregunta clara.
Ver prompt completo
Trabaja sobre el HTML adjunto de VAXA. Inspecciona primero qué funciones ya existen y conserva las que funcionan.

Transfórmalo en un simulador educativo para explorar esta pregunta: «¿Qué cambia cuando un atleta entrena en calor y modificamos la carga?».

El usuario debe poder configurar ambiente, duración, intensidad y tolerancia gastrointestinal; guardar un escenario A, cambiar una o dos variables y compararlo con B. Muestra por separado: variable modificada, respuesta fisiológica plausible, decisión que podría considerarse y dato que aún habría que medir.

Mantén la visualización central y haz que los controles cambien tanto la escena como la explicación. Etiqueta datos ingresados, cálculos, reglas educativas e hipótesis. Nunca presentes una tasa de sudor, un riesgo clínico o una necesidad individual como si se hubieran medido.

Entrega el HTML autónomo completo y una lista breve de pruebas realizadas, incluyendo celular, comparación A/B y datos faltantes.
Salida: simulador educativo.
07 / 09 · SECUENCIA 1/3Editorial

Guía editorial personalizada

Transforma un resumen clínico estructurado en una guía deportiva A4 de tres páginas, con cronología y decisiones ejecutables.

Necesitas: contexto trazable de NotebookLM y decisiones validadas.
Ver prompt completo
Actúa como un equipo interdisciplinario integrado por un nutriólogo deportivo basado en evidencia, un diseñador editorial especializado en publicaciones deportivas, un diseñador UX/UI y un desarrollador frontend experto en HTML y CSS.

OBJETIVO
Transforma la información clínica y deportiva proporcionada en una guía personalizada, útil y visualmente excepcional.

No quiero una dieta genérica ni una aplicación con apariencia de plantilla generada por IA. Quiero un documento editorial que un atleta pueda leer, entender y ejecutar.

FUENTE DE INFORMACIÓN
Utiliza los datos del paciente, historial, transcripción de consulta y protocolos proporcionados.

Distingue información confirmada, decisiones clínicas y datos pendientes. No inventes fechas, síntomas, porciones ni hábitos.

DIRECCIÓN VISUAL
- Estética editorial premium inspirada en publicaciones de rendimiento deportivo.
- Verde noche: #102932
- Verde petróleo: #006D65
- Papel marfil: #FBFAF5
- Acento lima suave: #E0ED98
- Titulares grandes, tipografía sans serif contundente y jerarquía clara.
- Abundante espacio en blanco, líneas finas, numeración editorial y cronologías.
- Evita tarjetas repetitivas, sombras excesivas, emojis e iconos decorativos.
- Cada página debe tener una identidad propia.
- No debe parecer una plantilla clínica.

ESTRUCTURA
Crea exactamente 3 páginas A4 verticales:

PÁGINA 1. CONTEXTO Y PREPARACIÓN
Portada editorial, situación del atleta, cronología de la última semana y prioridades.

PÁGINA 2. ALIMENTACIÓN Y LOGÍSTICA
Horarios, comidas familiares, porciones, viaje, lista de compras, digestión e hidratación.

PÁGINA 3. DÍA DE COMPETENCIA
Línea de tiempo desde despertar hasta recuperación, combustible, plan alternativo y checklist.

CRITERIOS CLÍNICOS
- Personaliza con alimentos y horarios documentados.
- Prioriza tolerancia, adherencia, seguridad y ejecución.
- Incluye alternativas solo cuando resuelven decisiones reales.
- Mantén advertencias clínicas relevantes.
- No inventes datos pendientes.
- Evita afirmaciones fisiológicas injustificadas.

REQUISITOS TÉCNICOS
- Un único archivo HTML completo.
- CSS incorporado.
- Sin dependencias externas indispensables.
- Diseño responsive para móvil y tablet.
- @page tamaño A4 vertical.
- @media print para imprimir exactamente 3 páginas.
- Conservar colores y evitar cortes de contenido.
- Botón para imprimir o guardar como PDF.
- Legibilidad y contraste adecuados.

PROCESO
Primero identifica las decisiones que el atleta necesita tomar.
Después organiza el contenido como narrativa visual.
Finalmente desarrolla el HTML completo.

INFORMACIÓN DEL PACIENTE:
[PEGAR RESUMEN ESTRUCTURADO DE NOTEBOOKLM CON DATOS FICTICIOS O DESIDENTIFICADOS]

ENTREGA:
HTML autónomo, listo para abrir, revisar, imprimir y publicar.
Salida: guía editorial A4.
08 / 09 · SECUENCIA 2/3Editorial

Auditoría de diseño y lectura

Revisa una primera versión sin perder decisiones clínicas; corrige jerarquía, composición y cortes de impresión.

Necesitas: el HTML del paso 07 y contenido ya validado.
Ver prompt completo
Actúa ahora como director de arte editorial y auditor de experiencia de usuario.

Revisa el HTML que acabamos de crear.

Conserva toda la información clínica validada, pero mejora radicalmente su presentación.

Quiero mayor jerarquía visual, títulos más potentes, composición equilibrada y una narrativa que pueda comprenderse de un vistazo.

No agregues contenido para llenar espacios.
No conviertas todas las recomendaciones en tarjetas.
No sacrifiques legibilidad por estética.

Cada página debe responder una pregunta diferente:
1. ¿Qué hago esta semana?
2. ¿Qué como y cómo me organizo?
3. ¿Qué hago el día de competencia?

Respeta exactamente tres hojas A4.
Revisa cortes de página, tamaño tipográfico, márgenes, densidad de texto y versión móvil.

Corrige lo necesario y entrega el HTML completo actualizado.
No elimines recomendaciones importantes ni inventes nuevas.
Salida: HTML corregido.

De la guía a una herramienta móvil

Extrae una decisión puntual del documento validado y conviértela en dos estrategias visibles y compartibles desde celular.

Necesitas: sección validada y datos de productos confirmados.

Convierte una sección de la guía del atleta en una microherramienta HTML mobile-first.

Presenta dos estrategias alternativas basadas exclusivamente en los productos y las recomendaciones suministrados.

Estilo editorial de alto contraste, diseño limpio, números grandes y poco texto.

No uses imágenes externas indispensables.
No necesitas animaciones ni elementos complejos.

Las dos opciones deben aparecer correctamente incluso si JavaScript no funciona.

El contenido clínico validado no debe cambiarse.
